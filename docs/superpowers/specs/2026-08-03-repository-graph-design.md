# Repository Graph and Search Policy Design

## Goal

Build a source-derived, incrementally maintained repository graph for the
OpenROAD `src/rsz` and `src/rmp` patch surfaces.  The graph gives the Teacher
precise, current code anchors and compact Doc Cards while preserving the
existing Markdown protocol, private Student workspaces, official evaluation,
and single-parent promotion semantics.

## Evidence and Scope

The inspected AuDoPEDA artifact contains OpenROAD/ORFS variants rather than a
separate public LLM evolution implementation.  Its useful demonstrated ideas
are bounded candidate selection, local validation before commit, rollback,
multi-metric acceptance, and explicit no-progress limits.  This design adopts
those principles at the controller level.  It does not copy its OpenROAD
implementation and does not claim an unavailable S0 graph implementation.

The checked-in P0 graph always covers production C++ implementation and header
files in both `src/rsz` and `src/rmp`; a design's narrower patch fence filters
the Teacher packet and remains enforced by the Controller. Headers participate
because they provide declarations and include dependencies. The graph never
parses build outputs, module test directories, or third party code.

## Repository Graph

`goalevolve/planning/repository_graph.py` owns all graph construction and
persistence. `RepositoryGraphIndex.build_p0()` writes the checked-in immutable
baseline, while `build_parent()` writes a source-hash-specific incremental
artifact for each campaign parent:

```
artifact_evaluation/lineage/openroad_power/p0/repository_graph/
  manifest.json
  graph.json
  doc_cards.json

<state_root>/knowledge/repository_graph/<source_hash>/
  manifest.json
  graph.json
  doc_cards.json
```

Each file entry contains a SHA-256 digest and parsed AST facts.  A new source
hash may reuse records from the newest compatible prior manifest when the
relative path and content digest match.  Changed, added, and deleted files are
handled independently; inter-file graph edges are recomputed from the resulting
complete node table so a newly added definition can resolve a pre-existing call.

Nodes are source facts, not LLM interpretations:

- `file`: a permitted C/C++ file;
- `symbol`: a named function, method, constructor, destructor, or class/struct
  definition with a stable ID based on relative path, qualified name,
  declarator, kind, line, and source digest.

Edges are deterministic and conservative:

- `contains`: file to symbol;
- `includes`: file to an include target only when it resolves inside the
  permitted surface;
- `calls`: function/method to a uniquely resolvable project symbol.  Ambiguous
  and external calls are retained as per-node unresolved call names but never
  fabricated as graph edges.

Tree-sitter supplies syntax and byte/line ranges.  Qualified names use lexical
namespace/class context, which avoids pretending to provide a full C++ type
checker.  The parser records recoverable parse errors but still indexes valid
definitions; a file with no valid AST root is reported in the manifest rather
than silently accepted.

## Graph Simplification and Doc Cards

The Teacher does not receive the raw full graph. `RepositoryGraph.focus()`
filters cards to the current design's configured roots and returns a bounded
selection around requested files, symbols, and diagnosis tokens. It prioritizes
hook names, C++ symbols that contain QoR/phase terms, direct callers/callees,
and source paths mentioned by validated EPD evidence. Bounded output is
deterministic and does not decide promotion. The packet is an induced subgraph:
it reserves a portion of its fixed symbol budget for one-hop AST callers/callees
of high-ranked seeds, closes selected symbols over their file nodes, removes
card relation targets outside that packet, and emits only `contains`,
`includes`, and `calls` edges whose endpoints are both selected.
`simplification` records seed, neighbour, backfill, selected/omitted symbol, and
induced-edge counts.

Doc Cards exist for each indexed file and editable symbol. A symbol card has:

- card ID and source hash;
- qualified symbol, parser-preserved declarator, kind, signature, path, line
  range, and source digest;
- containing type/namespace;
- resolved inbound/outbound symbol references;
- unresolved called names and metric tokens observed in source;
- source evidence syntax accepted by the controller:
  `relative/path.cc::qualified::symbol`, or the full qualified declarator for
  an overload. Multiple Markdown anchors use semicolons to preserve commas in
  C++ parameter lists.

Cards are generated directly from the AST and graph, not prose generated by an
LLM.  That makes them stable, traceable, and refreshable after a promoted source
change.

## Teacher and Controller Integration

At the beginning of each Codex Teacher round, `EvolutionEngine` indexes the
official parent snapshot.  It persists full graph artifacts, then supplies a
compact Doc Card view plus an artifact path in the existing Teacher prompt.  The
Teacher keeps returning the existing Markdown field blocks and still must read
the live parent source.  It can cite a qualified graph anchor.

`materialize_teacher_assignments()` validates each source hook and evidence
anchor with the current graph instead of a plain substring search.  Legacy
`path::short_symbol` remains accepted only if it resolves to exactly one symbol
in that file; otherwise a Teacher repair turn is required.  This preserves
existing historic plans while eliminating accidental textual anchors.

The existing regex structure index becomes a compatibility wrapper around the
compact graph view so external callers retain their public function name while
new engine use gets AST facts.

## Search Policy

`goalevolve/planning/search_policy.py` derives an advisory policy from existing
EPD evidence, diagnosis, and graph cards.  It cannot select a Parent, relax
promotion, create a Student role, or cause an unverified patch to be inherited.
It writes `rounds/round_NNN/search_policy.json` and provides the Teacher with:

- stagnation count based only on prior completed official rounds with no
  promotion;
- ranked focus cards based on evidence status, measured positive gain,
  source-hook occurrence, and diagnostic relevance;
- diversification constraints after repeated no-promotion rounds;
- a stagnation frontier derived from persisted `round.json` summaries: each
  recent failed attempt's hooks, evidence state, activation, and distance gain,
  plus repeated exact hooks that should not be retried without a materially
  distinct decision boundary;
- `elite_record_ids` derived from existing EPD `validated` records only;
- an explicit hill-climb state naming the current official parent as the sole
  accepted incumbent.

The EPD remains the evidence ledger and existing Integrator/Enhancer role source.
The policy ranks attention and tells the Teacher what evidence to revisit; it
does not silently turn local-only or promising source into a new parent.

## Failure Handling

Missing tree-sitter bindings cause a clear `RepositoryGraphUnavailable` error at
the Codex-Teacher boundary, with no fallback to unverifiable regex admission.
Malformed individual C++ files are recorded and excluded from symbol admission.
Graph artifacts are atomic JSON writes.  An existing parent graph can never be
reused for a different source hash.

## Verification

Unit tests use small synthetic `rsz`/`rmp` trees to establish AST symbol and
edge extraction, qualified anchor validation, doc-card rendering, and incremental
reuse/reparse behavior.  Engine tests verify that a Codex Teacher round writes
the parent graph artifact, embeds the compact cards, persists search policy, and
continues to reject ambiguous anchors.  The full existing unit suite remains the
regression gate; no full OpenROAD campaign is required for this controller-only
change.
